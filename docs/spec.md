# EPUB 读书伴侣 — 需求规格（v1）

## 1. 目标

导入 EPUB，设置阅读进度，基于**已读章节**生成前情提要，**绝不剧透未读内容**。

- **v1 范围**：书库管理、进度设置、前情提要（逐章摘要 / 整体剧情回顾 / 上次读到哪）。
- **后续版本**：人物表（v2）、基于已读内容的问答、登录与多用户、部署到自有 Linux 服务器。

## 2. 核心原则：防剧透

这是本产品的第一约束，优先级高于一切功能和体验。

1. **未读内容永不发给模型。** 代码中只有一个入口函数负责取出"可发送给 LLM 的章节"（如 `readable_chapters(book_id)`），所有生成逻辑必须经由它，禁止其他路径读取章节原文发往 LLM。需有单元测试覆盖该边界。
2. **按需生成。** 只为已读且缺缓存的章节生成摘要，不在导入时预处理全书。
3. **不向模型透露书名、作者、ISBN 等元数据**，避免模型调用自身对名著的记忆。章节标题如果含有剧透性信息也属于"已读"范围，可以正常传。
4. **Prompt 约束**：系统提示明确要求"只依据提供的文本，不得补充、推测或预告文本之外的任何情节"。
5. **名著兜底约束**：即使不传书名，模型仍可能从文本认出名著。所有生成类请求的系统提示都必须包含以下兜底条款（见 §2.1）。
6. 进度回退时，只展示新进度范围内的内容；超出新进度的已缓存摘要保留在库中但**不展示、不参与汇总**。

### 2.1 名著兜底 prompt 条款

所有发往 LLM 的生成请求（逐章摘要、切块摘要、整体回顾）共用一段固定的系统提示条款，集中定义在一处，不得在各调用点各写一份：

- 你可能认出这部作品，但必须**当作第一次读**：只使用本次提供的文本和摘要，不得使用你对这部作品、其续作、改编作品或相关评论的任何已有知识。
- 不得提及或暗示作品名、作者、系列名。
- 不得预告、暗示或评价后续发展，禁用"后来""最终""伏笔""这将导致"等指向未来的说法。
- 人物的身份、关系、真名只按已提供文本揭示的程度描述；文本中还是化名、谜团或未揭晓的，摘要中也保持原样。
- 不得补充文本中没有出现的人物、地点、事件。
- 不确定某个信息是否出现在提供的文本中时，宁可省略。

## 3. 关键概念

### 3.1 章节

- 以 EPUB **目录（TOC：EPUB3 nav / EPUB2 NCX）** 为准，嵌套目录**展平到叶子节点**，每个叶子节点算一章；展示时带上父级标题（如"第一卷 · 第三章"）。
- TOC 缺失或为空时，回退为按 spine 顺序每个文件算一章。
- 章节正文 = 从该叶子节点指向的位置（`href#anchor`）起，到下一个叶子节点指向的位置为止，可能跨越多个 spine 文件，也可能只是某个文件的一部分。
- 导入后用户可**勾选跳过**非正文章节（序言、版权页、致谢等）。被跳过的章节不生成摘要、不参与汇总，但仍占据进度序号。

### 3.2 进度

- 用户设置"**正在读第 N 章**"，即第 1 ~ N-1 章为已读，**第 N 章及之后都视为未读**。
- 设为第 1 章时没有已读内容，提要页提示"还没有可回顾的内容"。
- 每本书独立记录进度。

## 4. 功能需求

### 4.1 书库

- 上传 `.epub` 文件导入；解析书名、作者、封面（仅用于界面展示）、章节列表。
- 书架列表：书名、作者、当前进度（第 N 章 / 共 M 章）。
- 删除书籍（连同其章节、摘要缓存）。
- 解析失败（DRM、损坏文件）时给出明确错误提示。

### 4.2 进度设置

- 在章节列表里选择"正在读的章节"。
- 章节列表中可勾选/取消"跳过（非正文）"。

### 4.3 前情提要

提要页包含三部分，均只覆盖第 1 ~ N-1 章：

**a) 逐章摘要**
- 每章一条，可展开查看。
- 每条摘要包含三个字段：
  - `summary`：本章主要情节。
  - `ending_state`：章末状态（场景、人物处境、悬而未决的事），供"上次读到哪"使用。
  - `names`：本章出场人物的名字记录，每人一条：统一称谓、别名/昵称、英文书的原文名。只记录本章文本里出现过的信息。
- 生成第 k 章时输入：
  1. 第 k 章原文；
  2. **最近 K 章**已读章节的摘要（第 k-K ~ k-1 章，跳过的章节不算），K 可配置，默认 3；
  3. **人物名单**：第 1 ~ k-1 章所有 `names` 合并去重的结果，要求模型沿用名单中的统一称谓。
- 人物名单只是内部用来保证称谓一致的上下文，不在界面上展示，也不等于 v2 的人物表。它完全由第 k 章之前的摘要合并而来，因此不会带入第 k 章及之后的信息。
- 结果**持久化缓存**；每章旁有"重新生成"按钮。重新生成某章不会自动重算后续章节，后续章节沿用已有缓存。
- 章节过长、超出模型上下文时，先切块分别摘要再合并成该章摘要；每个切块请求都带同样的最近 K 章摘要和人物名单。
- 缺失的摘要按章节顺序依次生成（后一章需要前面章节的摘要和人名作上下文），界面显示生成进度。

**b) 整体剧情回顾**
- 基于第 1 ~ N-1 章的**逐章摘要**再总结，**不重新读原文**。
- 缓存键 = 书 + 进度 N + 所用各章摘要的版本；任一参与的章节摘要被重新生成，或进度变化时，缓存失效并重新生成。

**c) 上次读到哪**
- 展示最近 1~2 个已读章节（N-1、N-2）的摘要，突出第 N-1 章的 `ending_state`，帮读者接上断点。
- 直接取逐章摘要缓存渲染，不额外调用模型。

### 4.4 输出语言

- 书籍可能是中文或英文，**提要一律输出中文**。
- 英文书的人名、地名首次出现时保留原文，如"伊丽莎白（Elizabeth）"。

## 5. 非功能需求

### 5.1 技术栈

| 层 | 选择 |
|---|---|
| 后端 | Python（建议 FastAPI） |
| EPUB 解析 | 建议 `ebooklib` + `BeautifulSoup` |
| 存储 | SQLite（单文件）+ 本地目录存放原始 EPUB |
| 前端 | 尽量简单：服务端提供的静态 HTML + 少量原生 JS，不引入构建工具；v1 不追求美观，能用即可 |
| LLM | DeepSeek API（OpenAI 兼容接口） |

### 5.2 配置

所有配置走**环境变量**（本地开发可用 `.env`，`.env` 不入库，提供 `.env.example`），代码中不得写死：

- `DEEPSEEK_API_KEY`
- `DEEPSEEK_BASE_URL`
- `DEEPSEEK_MODEL`
- `DATA_DIR`（SQLite 文件和 EPUB 存放目录）
- `HOST` / `PORT`
- `APP_ENV`：`development` / `production`，默认 `production`
- `SUMMARY_CONTEXT_CHAPTERS`：逐章摘要时带入的最近章节数 K，默认 3

### 5.3 LLM 请求日志（开发模式）

- 仅当 `APP_ENV=development` 时开启；生产环境不记录。
- 每次调用 LLM 都追加一条记录到 `DATA_DIR/logs/llm_requests.jsonl`，一行一条 JSON，包含：时间、请求类型（逐章摘要 / 切块摘要 / 整体回顾）、book_id、章节序号、模型名、请求参数、完整的 messages（系统提示 + 用户内容）。
- **不得记录 API key 和任何请求头**。日志由统一的 LLM 调用封装写入，不在各调用点各自打日志。
- 这份日志也用于验收标准 2 的人工核查。

### 5.4 为后续版本预留

- **登录 / 多用户**：数据表预留 `user_id` 字段（v1 固定为单一默认用户），进度和书籍归属都按用户隔离。
- **部署**：能在 Linux 服务器上以单进程运行，数据全部落在 `DATA_DIR`。
- **问答**：复用同一个 `readable_chapters` 边界。

## 6. 数据模型（草案）

- `books`：id, user_id, title, author, file_path, cover_path, current_chapter (N), created_at
- `chapters`：id, book_id, number（展平后的序号，从 1 开始）, title, parent_titles, start_href, skipped, text（导入时抽取的纯文本）
- `chapter_summaries`：id, chapter_id, summary, ending_state, names（JSON）, version, model, created_at
- `recaps`：id, book_id, up_to_chapter, source_versions_hash, content, created_at

## 7. v1 不做

- 人物表（v2）
- 问答
- 登录、多用户、线上部署
- 内置阅读器、与其他阅读器同步进度
- 章内精确位置（只到章级别）
- 自动审查提要是否越界（v1 依靠 §2 的措施）
- 其他 LLM 提供商

## 8. 验收标准

1. 能导入一本带嵌套目录的中文 EPUB 和一本英文 EPUB，章节列表正确展平。
2. 设置"正在读第 N 章"后，通过开发模式日志检查实际发往 DeepSeek 的请求，确认其中不包含第 N 章及之后的任何原文，也不包含书名和作者。
3. 每个生成请求的系统提示都包含 §2.1 的名著兜底条款。
4. 生成第 k 章摘要的请求中，只带最近 K 章摘要和由第 1 ~ k-1 章合并的人物名单。
5. 生产模式下不产生 LLM 请求日志；开发模式日志中搜不到 API key。
6. 逐章摘要生成一次后，再次打开提要页不再调用模型。
7. 重新生成某章摘要后，整体回顾随之更新。
8. 进度回退后，提要页不再出现超出新进度的内容。
9. 英文书的提要为中文。
10. 仓库中搜不到任何 API key。
